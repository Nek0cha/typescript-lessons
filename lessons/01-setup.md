# 環境構築は3つ：Node.js・pnpm・VS Code

TypeScriptを書くために必要な道具は3つです。JavaScriptを実行するための「Node.js」、パッケージを管理するための「pnpm」、コードを書くためのエディタ「VS Code」。この章ではこの3つを順番にインストールします。

対応OSはWindows・macOS・Linuxのいずれでも構いません。手順に大きな違いはありませんが、コマンドの一部が異なる箇所は明記します。

## 1. Node.jsをインストールする

Node.jsは、ブラウザの外（パソコン上）でJavaScript（およびTypeScriptをコンパイルした結果）を実行するためのソフトです。TypeScript自体を動かすためにも必要になります。

[nodejs.org](https://nodejs.org/)にアクセスし、LTS（Long Term Support、長期サポート版）と書かれたバージョンをダウンロードしてインストールしてください。執筆時点ではNode.js 22系がLTSです。奇数バージョン（21、23など）は開発版なので避けてください。

インストールできたか確認します。ターミナル（Windowsの場合はコマンドプロンプトやPowerShell）を開いて次を実行してください。

```bash
node --version
# v22.x.x のような表示が出ればOK
```

バージョン番号が表示されればインストール成功です。「コマンドが見つかりません」というエラーが出た場合は、インストール後にターミナルを再起動していないことが多いので、ターミナルを一度閉じてから開き直してください。

## 2. pnpmを使う理由

Node.jsには標準で`npm`というパッケージ管理ツールが付属しています。パッケージ管理ツールとは、他の人が作った便利なコード（パッケージ、あるいはライブラリと呼びます）を自分のプロジェクトに取り込むための仕組みです。このシリーズでは、標準の`npm`ではなく`pnpm`という別のツールを使います。

理由は3つあります。

**1つ目は、ディスク容量の使い方です。** `npm`は、パッケージをインストールするたびにプロジェクトごとの`node_modules`フォルダにファイルの実体をコピーします。10個のプロジェクトで同じパッケージを使っていれば、同じファイルが10か所に重複して保存されます。`pnpm`はパソコン内の共有ストレージにファイルの実体を1つだけ持ち、各プロジェクトからはそこへのリンクを張る方式を取ります。パッケージを多く使うプロジェクトを複数持つようになると、この差は数GB単位で効いてきます。

**2つ目は、「幽霊依存」が起きにくいことです。** `npm`は`node_modules`の中にあるパッケージを平坦に展開するため、実は`package.json`に書いていないパッケージまで`import`できてしまうことがあります。手元では動くのに、他の人の環境やCI（自動テスト環境）ではエラーになる、という事故の原因になります。`pnpm`は依存関係の構造を厳格に保つため、明示的にインストールしたパッケージしか使えません。事故が本番環境で発覚するより、自分の手元で早めに気づけたほうが安全です。

**3つ目は、速度です。** ファイルの実体をコピーせずリンクで済ませる分、インストールが`npm`より速くなる傾向があります。

これらはpnpm公式のベンチマークやアーキテクチャ上の設計に基づく一般的な傾向であり、パッケージの数や種類によって体感差は変わります。とはいえ、学習用の小さなプロジェクトであっても`npm`から`pnpm`に切り替えるコスト自体はほぼゼロなので、最初から`pnpm`に慣れておくのが合理的です。

### pnpmをインストールする

```bash
npm install -g pnpm
```

`-g`は「グローバルにインストールする」という意味のオプションで、パソコン全体でどこからでも`pnpm`コマンドを使えるようにします。インストールできたか確認します。

```bash
pnpm --version
# 9.x.x のような表示が出ればOK
```

## 3. VS Codeをインストールする

エディタは[Visual Studio Code](https://code.visualstudio.com/)（通称VS Code）を使います。TypeScriptを作っている会社（Microsoft）が同時に作っているエディタなので、TypeScriptとの相性が最も良く、追加の設定なしに型エラーがエディタ上に赤線で表示されます。

公式サイトからダウンロードしてインストールしてください。インストール後、日本語で使いたい場合は、左側のメニューにある四角が4つ並んだアイコン（拡張機能）から「Japanese Language Pack」を検索してインストールすると、メニューが日本語表示になります。

## 動作確認：プロジェクトを1つ作ってみる

最後に、これから使う作業用フォルダを1つ作って、ここまでの3つが噛み合っているか確認します。

```bash
mkdir ts-lesson
cd ts-lesson
pnpm init
```

`pnpm init`を実行すると、そのフォルダに`package.json`というファイルが作られます。これは「このプロジェクトにどんなパッケージが必要か」を記録する台帳のようなファイルで、以降の章で何度も出てきます。中身は次のようになっていれば成功です。

```json
{
  "name": "ts-lesson",
  "version": "1.0.0",
  "description": "",
  "main": "index.js",
  "scripts": {
    "test": "echo \"Error: no test specified\" && exit 1"
  },
  "keywords": [],
  "author": "",
  "license": "ISC"
}
```

このフォルダをVS Codeで開いてください（ターミナルで`code .`と打つか、VS Codeのメニューから「フォルダを開く」を選びます）。ここまでできれば環境構築は完了です。
