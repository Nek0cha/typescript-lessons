# 変数はletかconstの2択、基本的にconstを使う

TypeScriptで変数を宣言する方法は3つありますが、実際に使うのは2つだけです。

```typescript
var oldStyle = "使わない";   // 古い書き方。挙動に癖があるため今は使わない
let count = 1;               // 再代入する変数
const name = "Neko";          // 再代入しない変数
```

`var`はJavaScriptの初期からある書き方ですが、スコープ（変数が有効な範囲）の扱いに癖があり、意図しないバグの原因になりやすいため、現在はほぼ使われません。`let`と`const`はその問題を解決するために後から追加された書き方で、このシリーズでも常にどちらかを使います。

使い分けの基準はシンプルです。**あとで値を変える予定がなければ`const`、変える予定があれば`let`。** 迷ったらまず`const`で書いてみて、コンパイラに「再代入してるよ」と怒られたら`let`に変える、という進め方でも問題ありません。

```typescript
const taxRate = 0.1;
taxRate = 0.08; // エラー: Cannot assign to 'taxRate' because it is a constant.

let stock = 10;
stock = 9; // OK: letは再代入できる
```

## 型注釈と型推論

00章で見た`price: number`のように、変数名のあとに`: 型名`と書くのが型注釈です。ただし、TypeScriptには型推論（type inference）という機能があり、代入した値から型を自動的に判断してくれるため、実際には型注釈を省略できる場面が多くあります。

```typescript
const age: number = 20; // 型注釈あり
const age2 = 20;        // 型注釈なし。TypeScriptが自動でnumber型と判断する
```

`age2`にカーソルを合わせると、エディタは自動的に`const age2: number`と表示します。これは「型が付いていない」のではなく「明示的に書いていないだけで、裏側では型が決まっている」状態です。

型注釈を省略できるのに、いつ明示的に書くべきかというと、主に次の2パターンです。

- 関数の引数（00章の`price: number`のように、代入する値がまだないので推論できない）
- 変数を宣言した時点では値が決まらず、あとから代入する場合

```typescript
let result: number; // まだ値がないので型注釈が必要
if (someCondition) {
  result = 1;
} else {
  result = 2;
}
```

## プリミティブ型

TypeScriptの基本的な型は次の7つです。JavaScriptにもともとある値の種類（プリミティブ型）がそのまま型名になっています。

| 型名 | 具体例 | 説明 |
|---|---|---|
| `string` | `"こんにちは"` | 文字列。シングルクォート・ダブルクォート・バッククォートのどれで囲んでも同じ |
| `number` | `42`、`3.14` | 数値。整数と小数を区別する型はなく、どちらも`number` |
| `boolean` | `true`、`false` | 真偽値 |
| `null` | `null` | 「値が存在しないこと」を意図的に表す値 |
| `undefined` | `undefined` | 「まだ値が代入されていないこと」を表す値 |
| `bigint` | `100n` | numberで扱いきれない大きな整数（末尾に`n`を付ける） |
| `symbol` | `Symbol()` | 一意の識別子を作るための型。このシリーズではほぼ使いません |

`null`と`undefined`はどちらも「値がない」ことを表しますが、使われ方に違いがあります。慣習として、`undefined`は「変数はあるがまだ値がセットされていない」自然な状態、`null`は「意図的に空であることを示した」状態として使い分けられることが多いです。この区別は言語仕様として強制されているわけではなく、チームやプロジェクトの慣習に近いものだと理解しておいてください。

## テンプレートリテラル：文字列の中に変数を埋め込む

02章のコードで使った、バッククォート（`` ` ``）で囲む書き方をテンプレートリテラルと呼びます。文字列の中に`${}`で変数を埋め込めます。

```typescript
const name = "Neko";
const age = 20;

// 従来の連結（+）でも書けるが、長くなると読みにくい
const message1 = "こんにちは、" + name + "さん（" + age + "歳）";

// テンプレートリテラルなら見た目のまま書ける
const message2 = `こんにちは、${name}さん（${age}歳）`;
```

文字列を組み立てる場面では、`+`による連結よりテンプレートリテラルのほうが読みやすいため、このシリーズでは基本的にこちらを使います。

## anyは「型チェックを諦める」型

TypeScriptには`any`という特殊な型があります。どんな値でも受け入れる型で、`any`を付けた変数は事実上、型チェックの対象から外れます。

```typescript
let value: any = "文字列";
value = 123;       // エラーにならない
value = true;      // これもエラーにならない
value.foo.bar.baz; // 存在しないプロパティを呼んでもコンパイル時にはエラーにならない
```

一見便利に見えますが、`any`を使うということは、そこだけTypeScriptを使わずにJavaScriptを書いているのとほぼ同じ意味になります。00章で説明した型の恩恵（補完・早期のミス検出）がすべて失われるため、このシリーズでは`any`は基本的に使いません。

「型が分からないけれど、とりあえずコンパイルを通したい」という場面では、代わりに`unknown`型を使います。`unknown`も任意の値を受け取れますが、`any`と違って「使う前に型を確認しないと使わせない」という制約が付きます。

```typescript
let value: unknown = "文字列";

value.length; // エラー: 'value' is of type 'unknown'.

if (typeof value === "string") {
  value.length; // OK: ここではvalueがstringだとTypeScriptが理解している
}
```

「値の中身を確認してから使う」という一手間を強制してくれるのが`unknown`です。詳しい絞り込みの仕組みは[06章](06-control-flow.md)で扱います。

## 確認問題

次のコードにはTypeScriptがエラーを出す箇所が1つあります。どこか分かりますか（答えは次の行の下に反転して書いています）。

```typescript
const userName = "Neko";
userName = "ねこ";
console.log(`ユーザー名: ${userName}`);
```

<details>
<summary>答えを見る</summary>

`userName`は`const`で宣言されているため、2行目の`userName = "ねこ"`が再代入エラーになります。再代入する予定があるなら、宣言時に`let userName = "Neko";`とすべきでした。

</details>
